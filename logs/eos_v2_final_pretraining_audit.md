## 2. Issue 1: Tree-Count Reconciliation

### 2.1 The Observed Discrepancy
* **Message Split (`conversation_split/`):** 3,212 training trees, 357 validation trees $\rightarrow$ **3,569 total trees**
* **Conversation Paths / EOS v2 (`training_sequences_eos_v2/`):** 3,137 training trees, 345 validation trees $\rightarrow$ **3,482 total trees**
* **Net Difference:** 75 training trees + 12 validation trees = **87 trees**

### 2.2 Root-Cause Investigation
Every conversation path generated by `src/build_paths.py` is constructed by recursively walking downward from root messages:
```python
def process_tree(indexes, clean):
    tree = clean.select(indexes)
    children = make_children(tree)
    paths = []
    for root in children.get(None, []):
        paths.extend(build_paths(tree, children, root, []))
    return [[indexes[i] for i in path] for path in paths]
```
In OASST1, a valid conversation path must begin with an initial user prompt whose `parent_id` is `None`. 

An exhaustive inspection of all 75 missing training trees and all 12 missing validation trees in `conversation_split/train` and `conversation_split/validation` revealed:
* **Missing training trees with `parent_id is None`:** **0 out of 75**
* **Missing validation trees with `parent_id is None`:** **0 out of 12**

Every one of these 87 trees consists exclusively of orphan replies whose original root message was filtered out during upstream English language selection (`data/processed/oasst1_en`). Because these trees contain no message with `parent_id == None`, `children.get(None, [])` returned an empty list `[]`, and `process_tree` produced exactly 0 conversation paths.

### 2.3 Split Isolation Proof
* `split_train_trees` (3,212) $\cap$ `split_val_trees` (357) = $\emptyset$ (**0 overlapping trees**)
* `paths_train_trees` (3,137) $\cap$ `paths_val_trees` (345) = $\emptyset$ (**0 overlapping trees**)
* `eos_v2_train_trees` (3,137) $\cap$ `eos_v2_val_trees` (345) = $\emptyset$ (**0 overlapping trees**)

**Conclusion:** No tree or conversation crossed from training into validation. The 87 trees were never part of any conversation path in the baseline clean dataset or in EOS v2.

### 3.3 Explanation of Discrepancy
The difference between source assistant turns (29,303) and packaged EOS tokens (28,084) is **not an implementation defect**. It is the direct geometric consequence of Design A's fixed 1,024-token context window:
* In 996 training conversations, total length exceeds 1,024 tokens.
* Truncating at token 1,024 cuts off 1,219 assistant turns that occur beyond index 1,023.
* Every assistant turn that falls within the 1,024-token capacity is fully preserved with its terminating `[EOS]` token.

### Detailed Verifications:
1. **User Prompt Text Isolation:** Exactly **0** user prompt text tokens receive `mask > 0`.
2. **Padding Exclusion:** Exactly **0** padding tokens (`[PAD]=0`) receive `mask > 0`. Padding occurs strictly as a contiguous trailing suffix in every sequence.
3. **Turn Boundary Deactivation:** Exactly **0** tokens immediately following `[EOS]` receive `mask > 0`. When input is `[EOS]`, target is `<|user|>` or `[PAD]`, and `loss_mask` is strictly 0.
4. **Shifted Next-Token Alignment:** In `CleanTokenDataset`:
   * `input_ids = seq[:-1]`
   * `target_ids = seq[1:]`
   * `loss_mask = mask[1:]`
   Whenever `target_ids == EOS_ID` (3), `loss_mask` is strictly 1 (all 28,084 in train, all 3,164 in val).
   Whenever `target_ids == USER_ID` (4) or `PAD_ID` (0), `loss_mask` is strictly 0.
5. **Assistant Role Tag Supervision:** The `<|assistant|>` token target (predicting `<|assistant|>` at the end of the user prompt) is supervised 29,010 times in train and 3,255 times in val, matching the baseline clean convention.
